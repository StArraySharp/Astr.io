## 零·二、真实服务器联调打通(2026-09-07 第三轮)

**目标**:本地镜像页面 + 重写客户端 → 直连原版线上服务器实际游玩。

### 线上结构勘误(爬取比对)

| 路径 | 内容 | 说明 |

### WebSocket 上云(关键决策)

- **Node ws 库直连原版 `/ws/*` 被 Cloudflare 401 拦截**(握手指纹检测;浏览器 WebSocket 直连 1.7s OPEN 成功)
- **方案:浏览器直连原版地址**——`GameConnection`/`ChatSocket` 支持 `__ASTRIO_LIVE_WS` 模式:`wss://www.astrio.io/ws/<mode>`、`wss://www.astrio.io/chat`;serve.mjs 自动注入开关(`ASTRIO_LOCAL_WS=1` 回退原版 localhost 端口表行为)
- 本地页面是 http,原版 ws 端点必须 **wss**(http 下降级 ws:// 会被 301)
- serve.mjs 保留 3000–3005 端口 ws 代理备用(消息级转发已验证)

### 真实服务器数据暴露的 3 个协议 bug(全部对照原版核实后修)

| # | 缺陷 | 原版依据 | 修复 |
|---|------|----------|------|
| 1 | `Keyboard.room` 对解构 const `pin` 重新赋值 → 严格模式 TypeError | bZ.room 对全局变量赋值,重写改 const 解构后语义破坏 | 局部变量 `pinOut` 等效 |
| 2 | `Keyboard.authResponse` 文档有实现无(222 号 auth 应答) | bZ.authResponse(220104 行):[222][u32] | 补齐方法 |
| 3 | `xssFilters.inHTMLData` 缺失(聊天 XSS 过滤,js-xss 库 API) | 页面全局 xssFilters.inHTMLData | 垫片补 `inHTMLData: escapeHtml` 别名 |

### 最终验证(截图确认)

`wss://www.astrio.io/ws/domination` OPEN → Codec 种子握手 → 进入战场:TestBot(质量 497)可见、真实玩家排行榜(Hulk/Vito 等 1.3k)、小地图扇区标记、TEAMS/ALLIES 面板、**Ping ~869ms**(真实跨境延迟)、聊天服保持连接、50 号世界更新帧解析正常。**整条"本地页面 → 原版服务器"链路可实际游玩。**

## 二、反混淆流水线(阶段 1)

### 障碍与解决

| 问题 | 解决 |
|------|------|
| webcrack 2.x 依赖原生模块 `isolated-vm`,gyp 编译失败导致进程硬崩(exit 127) | 降级 webcrack 1.9.1(vm2,纯 JS) |
| 内嵌库存在**第二层混淆**(RC4 式 `ab(idx,key)` 解码器 + 代理对象转发 + 偏移包装器链) | 提取 `a9/aa/ab/旋转器` 到沙箱预执行(`inner-prelude.js`),得到真实解码函数 |
| 代理对象求值的编译顺序/循环依赖问题(残缺闭包被永久缓存) | 自研惰性 `with(Proxy)` 环境:函数自由变量在**调用时**解析 |
| 隐式全局变量(`for(cp=...)` 未声明)被纯度检查拒绝 | `with(__scratch)` 沙箱层接住隐式全局读写 |
| 控制流扁平化(`"3\|9\|8\|2\|7\|4\|0\|5\|1\|6".split('\|')` 顺序分发) | 反扁平化 pass(50 处)+ eval-safe 分类档 |
| webcrack 二次处理把属性改写成方法简写(ObjectMethod) | 分类器/编译器全面支持 ObjectMethod |
| 折叠误伤赋值左侧成员(`f1.k = fn` 的 `f1.k` 被当读取替换导致崩溃) | tryFoldMember 增加赋值/更新/delete 目标守卫 |
| Windows 大小写不敏感导致提取文件互相覆盖(bj/bJ、bh/bH 等) | 代理们按字节偏移从 bundle 重新提取 |

### 结果

- 外层:内联 178,893 个解码调用、解密 176,958 个字符串
- 内层:keyed RC4 调用清零、代理调用内联 48,824 处(`eE` 引用 22,063 → 46)
- 最终 6.6MB / 22.1 万行,`@babel/parser` 解析 0 错误
- 安全模型:仅当函数经验证无外部副作用且实参全可解析时才求值;异常一律捕获跳过(运行时语义不受影响)
- 原版缺陷考证:Store 旧键清理循环永不生效(5 字符子串比 6 字符前缀);ChatSocket `connected` 从不置 true——均按可观察行为保留并注释

## 五、WASM 逆向(阶段 4)

**对象**:`codec.wasm`(8.7KB,23 导出,AssemblyScript 产物),从 www.astrio.io 下载;`npm i wabt` 反汇编为 178KB WAT。

### 流密码(与 wasm 差分验证 96/96)

```
核心:xorshift128 变体
  t = d ^ (d << 11)
  [a,b,c,d] ← [a ^ t ^ (t>>>8) ^ (a>>>19), a, b, c]
密钥流字:m = imul(newA, 0x5BD1E995)   ← MurmurHash 乘数,4 字节小端异或
加密方向 q1:种子 ⊕ [0xA5A5A5A5, 0x5A5A5A5A, 0xF0F0F0F0, 0x0F0F0F0F],预热 16 步
解密方向 q2:种子 ⊕ [0x12345678, 0x9ABCDEF0, 0xDEADBEEF, 0xCAFEBABE],预热 16 步
特性:双向独立流;状态跨调用持续;尾部(非 4 倍数)单步补齐
```

破解路径:行为分析确认 XOR 流密码 → 候选算法(RC4/ChaCha/xorshift 等)全不匹配 → 读 WAT 小函数(q1/q2/p5/p6 共 142 条指令互相印证)→ 测试向量法消歧(期间发现自己实现的移位 bug 导致周期 16)。

### p9 挑战哈希(18/18 一致)

br_table 混淆的 2,569 指令函数 → 写 WAT 指令级解释器(`p9Interpreter.js`)忠实执行,混合 (a, b, k7 种子全局)。指令数据由 `scripts/gen-p9-ops.mjs` 从 WAT 机械生成。

### 其余

`v1()=3`、`d0()=256`;m1..m6/h1..h3(h3 含 SHA-256 IV)等导出未被游戏调用。`Codec.js` 双后端:优先 wasm,失败回退纯 JS。

## 八、方法论沉淀

1. **行为验证优先**:凡语义存疑(代理运算符、怪癖),一律用沙箱内真实对象执行确认,不靠猜
2. **差分测试**:JS 实现与 wasm 逐字节对比(96 向量),解释器与 wasm 对比(18 向量)
3. **保守折叠**:求值失败即跳过,保证输出与原版行为等效而非"看起来对"
4. **死代码识别改变问题规模**:6MB `ad` 剔除后,重写范围从"不可能"变为"380KB 可行"
5. **并行代理 + 单一事实源**:所有代理读同一 bundle 与映射表,冲突(大小写覆盖)按偏移回源解决
